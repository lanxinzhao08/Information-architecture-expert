# Information Architecture Rules

The reviser reads this whole file on every request and asks the model to
restructure the documentation section so it follows these rules. Edit freely:
plain prose, numbered lists, or headings all work. If this file is empty, a
built-in default (the three rules below) is used.

## Rule A: Shallow and balanced
Keep the tree at most 3 levels deep below the root, and give each page at most 8 children.

## Rule B: Group by topic and user task
Place related pages under the same parent, ordered by user journey (overview, concepts, how-to, reference). A page's parent must be the page that best introduces or summarizes it.

## Rule C: One home per page
Every page appears exactly once. Avoid near-duplicate sibling topics by placing overlapping pages next to each other under one parent.
